## 2026-11-08：back と front の TypeScript のバージョンをどうそろえるか

**困ったこと**

`npm create` で作った直後、back は TypeScript 7.0、front は6.0だった。バージョンが違うと型の解釈がずれるおそれがある。

**AIに聞いたこと**

どちらのバージョンにそろえるのがよいか。

**採用したこと**

両方 `~6.0.3` にそろえた。front の ESLintが TypeScript 6.0までしか対応していないため。

**採用しなかったこと**

両方7.0にそろえる案。typescript-eslint が7.0に対応するまで、front の Lint が動かなくなるため。

## 2026-11-08：登録した感想の反映方法

**困ったこと**

提案する服装に感想を反映させる方法で迷った。

**AIに聞いたこと**

A（体感温度をずらす）と B（段階をずらす）の比較をしてもらった。

**採用したこと**

A。体感温度をずらすことで細かく調整できると判断したため。

1℃ずつずらすようにして、上限を7℃、反映する日も過去1週間にした。
増減の上限を決めることで暴走を防ぎ、期間も決めることで夏の感想が冬に反映されることを防ぐため。

**採用しなかったこと**

B。服装の段階をずらすと大きく変わりすぎてしまうと判断したため。

## 2026-11-08：降水確率が1時間だけ基準を上回った際に傘を提案するか

**困ったこと**

降水確率が1時間だけ40%を上回った際に傘を提案するかどうか。

**AIに聞いたこと**

提案する場合、しつこくならないか。

**採用したこと**

提案する。提案する際に「最大降水確率〇%(16時)」のように表示することでユーザーに判断を委ねるようにすれば、より柔軟に対応できるため。

**採用しなかったこと**

提案しない。毎回提案するとしつこいとは思ったが、折りたたみ傘を用意して使わないより、傘を持っていなくて濡れるほうが困ると判断したため。

## 2026-11-24：感想が 1 件だけでも体感温度に反映するかどうか

**困ったこと**

感想が 1 件だけでも体感温度に反映してもいいか

**AIに聞いたこと**

感想が 1 件だけでも体感温度に反映する際のデメリット

**採用したこと**

感想が 1 件だけでも体感温度に反映する。すぐに反映されるので、使い始めたばかりの人にも効果が見えるため。

## 2026-11-24：PORTの値がおかしい時の処理

**困ったこと**

PORTの値がおかしい時は規定値で起動するのではなく、エラーで起動を止めたほうがいいのか

**AIに聞いたこと**

それぞれのメリットとデメリット

**採用したこと**

エラーで起動を止める。console.errorで出すことでEC2でjournalctlで見ることができるため。

**採用しなかったこと**

規定値で起動する。黙って規定値で起動すると設定ミスに気づけないため。
